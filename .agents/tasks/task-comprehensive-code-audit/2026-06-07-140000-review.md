# Comprehensive code audit: force-join, dead code, unicode bug, delivery parity

A sweep of bot.py addressing nine distinct issues that accumulated across prior feature work. The force-join check is lifted out of the `/start` handler into `AuthMiddleware` so it gates all user actions. Three admin handlers that compared unicode-bold button text using `.lower()` are fixed (bold characters don't lowercase the same way as ASCII). A dead handler (`admin_to_home`) unreachable due to router priority is removed. Proxy auto-delivery now sends an xlsx file matching the mail flow. The deposit back-navigation bug (lost payment number) is fixed by persisting `pay_number` in FSM state. The stock export loop respects `interval=0` as "disabled." A shared `_check_low_stock_alert` helper replaces two duplicate alert blocks.

**Watch for:** Force-join failure is silently swallowed (confirmed) — a misconfigured channel ID will let all users through without warning. The negative-balance warning is cosmetic only (confirmed) — `update_balance` still permits negative balances, so the admin could unknowingly create a debt the user has no way to repay. Duplicated force-join check in `/start` is now redundant but not removed (confirmed).

## High-level view

The force-join enforcement moves from a single checkpoint at `/start` to a middleware-level gate that runs on every message and callback. This closes the gap where users who joined via deep-link or pressed a cached button could bypass channel membership, but it also means the `/start` handler's own force-join check is now duplicate work — harmless but wasteful.

The unicode `.lower()` fix addresses a silent failure: button constants use a `_b()` helper producing unicode bold characters (U+1D400 range) that don't respond to `.lower()`. The three admin handlers would never match the Back/Home buttons, causing button presses to be treated as credential input.

The proxy flow now sends an xlsx receipt file and the low-stock alert code is extracted into a shared helper that also adds the previously-missing out-of-stock notification to the proxy path.

The deposit back-navigation fix stores `pay_number` in FSM state so when a user hits Back from the TRX-entry step, the payment info screen still shows the correct number instead of an empty string.

## Force-join moved to middleware — fail-open on error

The middleware calls `check_force_join` for every non-admin event, skipping only `BTN_SUPPORT` messages. The concern is the error path:

```python
except Exception:
    pass  # If force-join check fails, allow access
```

If the bot is not an admin in the required channel (common misconfiguration), `get_chat_member` raises an exception, the check is swallowed, and users flow through as if they joined. In a production bot where force-join drives channel growth, failing open on config errors is a business risk. At minimum, log the exception.

Meanwhile, `cmd_start` at line 2592 still performs its own `check_force_join` with a richer UI (inline keyboard with join links and a "Check Again" button). The middleware's plain-text message doesn't offer this. Two resolutions: remove the `/start` duplicate and improve the middleware message, or keep both and document the layered intent (middleware blocks actions, `/start` provides onboarding UX).

## Unicode bold `.lower()` comparison fix

The three admin handlers previously had:

```python
if message.text and message.text.lower() in ("/cancel", BACK_BTN, HOME_BTN):
```

`BACK_BTN` and `HOME_BTN` contain unicode bold characters from `_b()`. These are in the Mathematical Alphanumeric Symbols block and do not lowercase to ASCII equivalents. So `message.text.lower()` would never equal `BACK_BTN` — the admin pressing Back/Home during VPN fulfill, proxy fulfill, or deposit reject would have their button text treated as credential input and forwarded to the user.

The fix:

```python
if message.text in (BACK_BTN, HOME_BTN) or (message.text and message.text.lower() == "/cancel"):
```

Exact equality for bold-text buttons first, `.lower()` only for the "/cancel" command.

## Proxy xlsx delivery and low-stock helper

The `_check_low_stock_alert` helper consolidates two inline implementations that had diverged: the proxy version's out-of-stock notification was missing entirely, and its low-stock message format didn't match the mail version. The helper normalizes both paths.

The helper's outer exception handler (`except Exception as _se: logger.warning(...)`) catches database failures during stock-count reads. If the database is persistently unreachable, no alerts will ever fire and the only signal is a warning log line that may go unnoticed.

## Negative balance: warning without prevention

`update_balance` unconditionally applies the delta with no floor:

```python
new_bal = round((user.get("balance") or 0) + delta, 4)
await db_update(f"users/{uid}", {"balance": new_bal})
```

The new warning surfaces the problem to the admin after the fact, but the damage is done — the balance is already negative in the database. Additionally, `current_bal = target_user.get("balance", 0)` is computed but never referenced in any logic or display, making it a dead assignment.
