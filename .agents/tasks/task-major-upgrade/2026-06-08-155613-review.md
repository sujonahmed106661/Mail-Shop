# Major Upgrade: User Panel, Admin Panel, UI Overhaul, and Referral Fix

This change adds roughly 2400 lines to the monolithic `bot.py`, introducing a user panel (VIP tiers, trending, favorites, search, restock notifications, repeat orders, statistics dashboard), an admin panel expansion (analytics breakdown, low stock alerts, price sync, auto import, role management, advanced search, transaction export, service status manager, profit calculator, activity logs), a dark-theme card formatting system with inline navigation, and a referral commission model that explicitly deducts from shop revenue rather than creating money.

Watch for: **`UserFlow.deposit_method` does not exist** — the `nav_deposit` callback will crash with `AttributeError` at runtime (confirmed). **Restock notifications are silently dead** — `Bot.get_current()` returns `None` in aiogram 3.15, so the subscriber notification path never fires (confirmed). **`nav_home` uses the wrong user identity** — `callback.message.from_user` is the bot, not the user who clicked (confirmed).

## High-level view

The referral system now explicitly frames commission as a shop revenue cost: the buyer pays full price, the referrer gets a percentage credited from the shop's margin, and each payout is logged to `referral_costs` for audit. The commission mechanics are unchanged (percentage of purchase credited to referrer's balance), but the accounting trail and documentation clarify the owner's exposure.

The restock notification feature connects `add_stock_items` to subscriber alerts via `asyncio.create_task`, but the notification function uses `Bot.get_current()` which is deprecated and returns `None` in aiogram 3.x without explicit context variable setup. The entire feature is non-functional despite being correctly wired.

Inline navigation callbacks (`nav_home`, `nav_balance`, `nav_mail`, `nav_history`, `nav_deposit`) let users jump between sections from any screen. The `nav_home` handler passes `callback.message` to `send_main_menu`, but `callback.message.from_user` is the bot instance, not the user — so the welcome message will show the bot's name and look up a non-existent user record. The `nav_deposit` handler references `UserFlow.deposit_method` which doesn't exist (the actual state is `dep_method`), causing an immediate `AttributeError`.

The admin quick-analytics callback sets `AdminFlow.analytics_detail` state but no handler consumes messages in that state, creating a dead-end where the admin must press HOME to escape. The advanced search "more results" button (`adm_search_more`) has no callback handler — clicking it does nothing.

Performance-wise, the trending, user stats, and admin analytics features all fetch the entire `orders`, `vpn_orders`, and `proxy_orders` collections from Firebase to filter client-side. This works at small scale but degrades as order volume grows.

## `nav_deposit` AttributeError

The `nav_deposit_cb` handler at line 3137 calls `state.set_state(UserFlow.deposit_method)`. The `UserFlow` StatesGroup defines the deposit state as `dep_method`, not `deposit_method`. In aiogram 3.x, accessing a non-existent attribute on a `StatesGroup` raises `AttributeError` immediately when the callback fires.

```python
# Line 3137 — will crash
await state.set_state(UserFlow.deposit_method)
# Should be:
await state.set_state(UserFlow.dep_method)
```

Additionally, the handler shows `main_menu_kb()` instead of `deposit_method_kb()`, so even after fixing the state name, users would see the wrong buttons.

## Restock notifications silently fail via `Bot.get_current()`

The `_notify_restock_subscribers` function (line 1073) imports `Bot` and calls `Bot.get_current()` to obtain the bot instance. In aiogram 3.x (specifically 3.15.0 as pinned), `get_current()` relies on `contextvars` that are only set within the deprecated `Bot.use()` context manager. Since the function runs inside an `asyncio.create_task` fired from `add_stock_items`, it executes outside any handler's context, and `get_current()` returns `None`. The function then returns early via `if not bot: return`, making restock notifications permanently inoperative.

The fix is to pass the `bot` instance as a parameter from the calling handler:

```python
async def add_stock_items(pid: str, items: List[str], bot: Bot = None) -> int:
    ...
    if was_empty and added > 0 and bot:
        asyncio.create_task(_notify_restock_subscribers(pid, bot))
```

## `nav_home` identity confusion

`nav_home_cb` (line 3063) calls `send_main_menu(callback.message, state)`. Inside `send_main_menu`, `message.from_user.id` is used to fetch the user profile and `message.from_user.first_name` for the greeting. When the message object comes from `callback.message`, its `from_user` is the bot (the entity that sent the message to the chat), not the user who clicked the inline button.

This results in: looking up a non-existent user in Firebase (returns `{}`), displaying the bot's first name in the greeting, and showing $0.00 balance. The other nav callbacks (`nav_balance`, `nav_history`) correctly use `callback.from_user.id`.

## Dead-end state: `AdminFlow.analytics_detail`

The `adm_quick:analytics` callback (line 6232) sets `AdminFlow.analytics_detail` and shows the admin main keyboard. No handler in the codebase is decorated with `AdminFlow.analytics_detail` as a state filter. The admin sees the keyboard but pressing any button (except HOME, handled by `router_global`) won't match any handler — the state filter on `AdminFlow.menu` handlers won't match, and these buttons don't match any text filter either.

## Referral revenue accounting gap

The referral system now logs commissions to `referral_costs` — a sound design for auditing. However, the profit calculator (line 9247) computes revenue from orders and subtracts `cost_price * units_sold`, but never fetches or subtracts the `referral_costs` entries. The profit figure is therefore overstated by the total referral commission paid out.

## `adm_search_more` dead button

The advanced search (line 8933) emits a button with `callback_data="adm_search_more"` when more than 10 results exist, but no `@router_admin.callback_query(F.data == "adm_search_more")` handler is registered. Clicking it leaves the user waiting with no feedback. Either implement pagination or show a message indicating pagination isn't implemented yet.

## Full-collection Firebase reads

`show_trending`, `show_user_stats`, `admin_analytics_detail_cb`, and `admin_profit_calc` each call `db_get("orders")`, `db_get("vpn_orders")`, and `db_get("proxy_orders")` which fetch the entire collection into memory. For a bot with thousands of orders, these reads will be slow and memory-intensive. This isn't a correctness bug but will become a scaling wall. For the trending/stats use case, maintaining a denormalized counter (incremented on purchase) would eliminate the full scan.
